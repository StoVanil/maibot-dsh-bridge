# DSH 话题制插件 · 实现方案（v2 · 决定已定稿 + P0 验证通过）

> 状态：设计已定稿，**P0（提问工具可行性）已实测通过**，尚未改动线上麦麦。
> 目标：把"一个聊天流一个工作区 + 每次任务一次性 dsh"升级为
> **话题 = 持久 dsh 会话 + 独立工作区 + 编号**，支持 dsh 反问、状态/报错回传、话题生命周期命令。

## 1. 总体架构

```
QQ（私聊）── 墨(MaiBot) ──┬── 桥插件（麦麦侧，Python，maibot-dsh-bridge → 0.7.0）
                         │      ├─ 命令解析：/dsh /新建 /修改话题 /删除话题 /话题 /恢复
                         │      ├─ 话题注册表 topics.json（编号、名字、session、目录、时间）
                         │      ├─ 调度：全局串行 + FIFO 队列
                         │      ├─ dsh 进程管理：spawn / 心跳 / 超时 / 终止 / 事件解析
                         │      ├─ 提问中转：ipc/questions → QQ；回答 → ipc/answers
                         │      ├─ 报错上报：事件 / 退出码 / 凭据 → 聊天
                         │      └─ 清理器：归档满 7 天删除并释放编号
                         │
                         └── dsh 子进程（cwd=话题目录，--session-id 续跑）
                                └─ MCP client → ask 工具（stdio，mcp__ask__ask_user）
                                      └─ dsh_ask_mcp.py（纯标准库，文件 IPC 读写）
```

## 2. 数据模型

`<data_dir>/topics.json`（原子写）：

```json
{
  "topics": [
    {
      "id": 3,
      "name": "修离线截图",
      "dir": "topic-3",
      "session_id": "session-4fc30e2f-...",
      "created_at": 1792843000.0,
      "last_used_at": 1792845600.0,
      "archived_at": null,
      "chats": ["<CHAT_STREAM_ID>"]
    }
  ],
  "current": { "<CHAT_STREAM_ID>": 3 }
}
```

**编号分配（半唯一）**

- 新话题取**当前所有话题（含归档未删除）中未占用的最小正整数**。
- 归档满 7 天、记录删除后，该编号回到可用池（下次新建可能复用 `#3`）。
- 编号一旦分配给新话题，永不与现有话题冲突 → `/dsh #3` 在任一时点含义唯一。

**目录**

```
<workspace_dir>/topic-<id>/        # 默认 <工作区根目录>/topic-3
├── AGENTS.md
├── uploads/          # QQ 发来的文件（index.json 索引）
├── ipc/              # questions/ answers/ mcp.log
├── ask-requests/     # 过渡期文件式提问（保留兼容）
└── ...dsh 产出
<workspace_dir>/.archive/topic-<id>-<ts>/   # 归档
```

## 3. 命令（全部收在 `/dsh` 下）

| 命令 | 别名 | 语义 |
|---|---|---|
| `/dsh <任务>` | — | 当前话题派活；无话题或闲置 >24h → 自动新建 |
| `/dsh #<id> <任务>` | — | 指定话题（归档话题拒绝，提示先 restore） |
| `/dsh new` | `/dsh 新建`、`/dsh est`、`/dsh 创建会话` | 建新话题并设为当前 |
| `/dsh set <名>` | `/dsh 修改话题 <名>` | 改当前话题名（≤12 字） |
| `/dsh del [#id]` | `/dsh 删除话题 [#id]` | 归档，7 天后删除并释放编号 |
| `/dsh restore #id` | `/dsh 恢复 #id` | 7 天内恢复为 active |
| `/dsh list` | `/dsh 话题`、`/dsh topics` | 列出；`/dsh list #3` 详情并切换 |
| `/dsh help` | `/dsh`（无参） | 用法说明 |

**命令拦截（v0.8.0）**：所有 `/dsh` 命令的处理器都返回拦截等级 1（`(ok, text, True)`），
Host 侧 `continue_process=False`，这批消息不再进入墨的对话流程，避免"墨来接话茬"。
解析规则：`-- ` 前缀强制当任务；编号容错 `#3`/`3`/`第3个`；中文全角括号；权限沿用 `[permission]`；
话题指令仅在私聊生效（群聊提示"只在私聊启用"）。

## 4. 生命周期与调度

```
(无) ──首任务──► active ──/del──► archived ──7d──► 删除（编号释放）
                    ▲                  │
                    └──────/恢复───────┘
```

- 自动新建：`now - last_used_at > topic.idle_hours(24)`。
- `last_used_at` 刷新点：任务开始、任务结束、提问发出/收到回答。
- 全局串行：一个 `_running` 令牌；FIFO 队列（元素含 topic_id），超 `queue_max` 拒绝。
- 每任务：解析话题 → 规划轮（生成 `plan/max_seconds/title`）→ 执行轮（`--session-id`）→ 回传。
- **等待提问时暂停无进展心跳**（否则 >180s 等待被误杀），恢复时重置计时。
- 归档话题：`/dsh #N` 直接拒绝；`/话题 #N` 只读展示。

## 5. 提问通道（MCP，已上线 P2）

### 5.0 生产 profile 已挂的 dsh 插件（headless）

| 插件 | 作用 |
|---|---|
| `@deepseek-ai/dsh-mcp-client` | 挂本地 ask MCP 服务器（stdio → `<MAIBOT_HOME>/scripts/dsh_ask_mcp.py`），工具名 `mcp__ask__ask_user` |
| `@deepseek-ai/dsh-tool-present` | dsh 用 `present` 声明交付文件 → 桥打包发 QQ |
| `@deepseek-ai/dsh-workspace-changes` | 每轮工作区变更摘要（会话事件） |
| `@deepseek-ai/dsh-skill-office` | Word/PPT/Excel 技能；解释器 `<office-venv 路径>/bin/python`（python-docx/pptx/openpyxl） |

headless profile 的 `cordis.patch.yml` 用 `- insert:` 挂载（备份在 `cordis.patch.yml.bak-p2-*`），`--dump-config` 已验证 4 条都在。

### 5.0.1 桥侧实现（P2）

- 任务运行期间起一个 1s 轮询的 watcher：见 `ipc/questions/*.json` → 发 QQ（带话题号、选项、有效期）→ 记 `mode=ipc` 的 pending
- 等回答时 `_ipc_waiting=True`：**暂停无进展心跳判定**（否则 >180s 会被当卡死杀掉），硬超时仍生效
- 用户回答 → 写 `ipc/answers/q-<qid>.json` → dsh 工具立刻返回 → 同进程继续
- 工具自身超时（问题文件被工具删掉）→ watcher 发现后清 pending、退出等待态并提示用户
- 桥的 `ask.timeout` 到期 → 写 `{"timeout":true}` 兜底
- 备用：`ask-requests/*.json` 文件通道保留（工具不可用时 dsh 回退），走续跑

### 5.1 组件

1. **MCP 服务器**：`<MAIBOT_HOME>/scripts/dsh_ask_mcp.py`（纯标准库，stdio，JSON-RPC 换行分隔）。
   - 工具：`ask_user(question, options?, note?, timeout_seconds?)`
   - 行为：写 `<topic>/ipc/questions/q-<qid>.json` → 轮询 `ipc/answers/q-<qid>.json`（500ms）→ 返回 `用户回答：X` 或超时提示。
2. **DSH 侧挂载**：headless profile 的 `cordis.patch.yml` 用 **`- insert:`** 插入一条 `@deepseek-ai/dsh-mcp-client`：

```yaml
- insert:
    - id: mcp-ask
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: ask
        transport: stdio
        command: <MAIBOT_HOME>/.venv/bin/python
        args: ['<MAIBOT_HOME>/scripts/dsh_ask_mcp.py']
        cwd: !!js process.cwd()
        toolCallTimeoutMs: 900000
        failOnStartupError: true
```

   > ⚠️ 关键坑：patch 文件里的 `- id: xxx` 是**按 id 覆盖已有条目**，不是新增；新增必须包在 `- insert:` 里，否则启动时提示 `patch: entry "xxx" not found` 且静默不生效。

3. **桥侧**（P2）：任务运行中每 1s 扫 `ipc/questions/` → 发 QQ → 等待态 → 用户回复写 `ipc/answers/` → 清等待态。

### 5.2 模型看到的工具名

`mcp__ask__ask_user`（`mcp__<serverName>__<toolName>`）。提示词/AGENTS.md 里告诉模型：需要用户拍板时调用它。

### 5.3 P0 实测结果（2026-10-24 21:12-21:15，隔离 profile `headless-mcp`，未动线上）

| 用例 | 结果 |
|---|---|
| 握手 / 工具发现 | ✅ `initialize` 回 `protocolVersion=2025-11-25`，`tools/list` 返回 1 个工具 |
| 正常提问 → 回答 → 继续 | ✅ 工具调用 → 写问题 → 外部写答案 → 返回 `用户回答：选 B` → dsh 同轮回复 `收到：B`（约 6s） |
| **长等待 90 秒** | ✅ 工具阻塞 90s 未被打断，返回答案，dsh 继续（总耗时 95s）→ `toolCallTimeoutMs` 生效，超时策略未误杀 |
| 超时降级（15s 无人回答） | ✅ 返回"用户未在 15 秒内回答（超时）…"，dsh 正常收尾（21s） |
| 重复启动 | ✅ mcp-client 先探测进程再起正式进程，日志可见两次启动 |

**结论**：MCP 路线可行，阻塞时长可控（按 `toolCallTimeoutMs`），长任务等待不会触发 DSH 工具超时策略。

### 5.4 协议文件

- 问题：`{"qid","question","options","note","timeout","created_at"}`
- 答案：`{"qid","answer","timeout":false,"answered_at","by"}`
- 超时：桥写 `{"timeout":true}`，工具返回超时提示（模型可自行决定或说明在等什么）。

## 6. 状态与报错上报

**状态**：受理 `🛠 #3（名字）已受理（超时 300s）`；运行心跳（可配）；提问；完成；归档/恢复；排队。

**报错源**：`tool_result` 失败汇总 / 进程 reason（timeout·stalled·loop·spawn-error）/ 退出码非 0 无 final / 凭据错误 / MCP 工具返回 isError。

**规则**：`⚠️ #3 dsh 报错：<原因>（日志 <路径>）`；同因 60s 去重；私聊直接发；路径与疑似密钥脱敏。

## 7. 归档与清理

- `/删除话题`：`archived_at=now`；目录 `mv topic-N .archive/topic-N-<ts>`；`current` 回退到最近 active 话题。
- 清理器：每天 03:00 + 启动后 30s 各一次；`archived_at + 7d < now` → 删目录、删记录、**编号释放**。
- `/恢复`：目录移回、清 `archived_at`；会话 id 保留（会话文件不在则首跑新会话并提示）。

- 懒认领：某聊天第一次派活时，若 `<workspace_dir>/<聊天流id>` 目录存在且**未被任何话题占用**，就把它认领成「遗留话题」（`#N（遗留·<hash 前 6 位>）`，目录沿用原目录），旧上传/产出/AGENTS.md 继续可用；否则新建 `topic-<id>` 目录。

> 从 dsh 事件流累加 `usage` 做用量预算 + 单工具调用超时（插件报状态），而不是回到拍脑袋的秒数。

## 12. 风险与对策

1. **长阻塞与心跳冲突** → P2 必须加"等待态暂停心跳"（P0 已验证工具侧可等 90s+）。
2. **MCP 工具超时** → `toolCallTimeoutMs=900000`（15 分钟）> `ask.timeout`；两者保持一致。
3. **patch 形式** → 必须 `- insert:`（已踩坑记录）。
4. **会话过期** → `--session-id` 失效时新开会话并在消息里提示。
5. **全局串行** → 长任务阻塞其他话题；后续可做每话题并行。
6. **报错脱敏** → 白名单化输出（只给文件名/相对路径，去 token）。
7. **dsh 升级** → mcp-client 配置格式与工具命名需复验（已有版本门禁教训）。

## 13. 开放问题（不阻塞 P1）

1. 全局串行还是每话题并行（默认先串行）。
2. 报错是否需要附日志文件上传（可后加）。
3. 归档话题的产出文件是否随归档整体移动（默认整体移动）。
