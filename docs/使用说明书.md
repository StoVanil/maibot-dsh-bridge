# DSH 话题（话题会话）· 使用说明书

> **状态**：已上线（桥插件 **v0.13.0**，2026-10-25）。
> **所有指令都收在 `/dsh` 下**（任务 + 话题管理 + 文件柜 + 权限 + 实验模式），命令消息会被桥**拦截**，墨不会接话茬。
> **适用范围**：只对**私聊**生效；群聊保持旧行为（不分话题）。
> **本版新增**：分场景帮助（`/dsh help 话题｜文件｜权限｜实验｜排障｜全部`）、按 QQ 号分目录的文件柜、文件路由调整、实验模式改成 QQ 指令开启、墨接入 file-reader 可直接读文件。

一句话：把 dsh 从"一次性的外包工人"变成"能接着上次聊的长期协作者"。
每个**话题** = 一条持久的 dsh 会话 + 一个独立工作目录 + 一个编号。你在 QQ 里派活，它在话题里干活，有疑问会问你。

---

## 0. 快速上手（30 秒）

```
/dsh 读一下我文件柜里的 package.json，说下是什么项目     ← 自动建 #1 并开始干
/dsh list                                                 ← 看有几个话题、当前是哪个
/dsh new                                                  ← 想换个方向就开新话题
/dsh set 课表整理                                          ← 给当前话题改名
/dsh del #1                                               ← 归档（7 天后自动删，可 restore）
/dsh files                                                ← 看自己的文件柜（按 QQ 号分目录）
/dsh help 文件                                             ← 只看法文件相关的帮助
/dsh help                                                 ← 记不住就看这个（总览 + 场景入口）
```

> `/dsh` 发命令时**墨不会插嘴**：命令由桥直接处理并回你，消息不会进墨的对话流程。

## 1. 核心概念

| 概念 | 说明 |
|---|---|
| **话题** | 一条持久的 dsh 会话。显示为 `#3（修离线图）` |
| **编号** | 自动分配 `#1`、`#2`…；**归档满 7 天被删除后，编号会被回收复用**（归档期间仍占号） |
| **话题名** | 先叫「新话题」，第一个任务后由 dsh 按规划轮给的名字（≤12 字）替换；可随时 `/dsh set` 改 |
| **工作目录** | `/root/DSH-work/mai/topic-3/`，话题的产出、附件、IPC 都在里面；改名**不会**动目录 |
| **会话** | 话题内部绑定一个 dsh `session-id`，同一话题的后续任务都续用它 |
| **遗留话题** | 首次使用时，你原来按聊天流建的目录（`mai/<聊天流id>`）还在且没被占用，就会认领成 `#1（遗留·af8e6f）`，旧文件继续可用 |

## 2. 话题是怎么来的

| 场景 | 行为 |
|---|---|
| 从没用过 | 第一次派活：有旧目录就认领为「遗留话题」，否则新建 `#1` |
| 当前话题 **24 小时内**用过 | 任务继续落在当前话题 |
| 当前话题 **超过 24 小时**没用 | 自动新建下一个话题，任务落到新话题 |
| `/dsh new` | 立刻建新话题 `#N（新话题）`，之后的任务落进去 |
| `/dsh #2 <任务>` | 指定话题执行，**不**自动新建 |
| `/dsh del` 归档 | 变**只读**：不再接收任务，要 `/dsh restore` 才能继续；7 天后自动删除、编号释放 |

## 3. 命令表（全部在 `/dsh` 下，中英双语）

| 命令 | 等价写法 | 作用 |
|---|---|---|
| `/dsh <任务>` | — | 在当前话题派活（必要时自动新建） |
| `/dsh #3 <任务>` | — | 指定话题派活；归档话题会被拒绝 |
| `/dsh --timeout 600 <任务>` | — | 给单次任务设时间上限（秒）；不写=不限时 |
| `/dsh -- new 一个页面` | — | `-- ` 开头强制当任务（正文碰巧以 new/del 开头时用） |
| `/dsh peek` | `/dsh status`、`/dsh 状态`、`/dsh 进展`、`/dsh 在干嘛` | 看它现在在干什么（步骤 / 工具 / 最近动静）；`status` 是英文别名 |
| `/dsh queue` | — | 看排队中的任务（第几位、还有几条） |
| `/dsh stop` | `/dsh 停止` | 立刻停下当前任务（产出文件会尽量发回来） |
| `/dsh stop 全部` | `/dsh 停止 全部` | 连排队中的任务一起清掉 |
| `/dsh new` | `/dsh 新建`、`/dsh est`、`/dsh 创建会话` | 新建话题并设为当前 |
| `/dsh set <新名字>` | `/dsh rename <新名字>`、`/dsh 修改话题 <新名字>` | 改当前话题名（≤12 字） |
| `/dsh del [#3]` | `/dsh archive [#3]`、`/dsh 删除话题 [#3]` | 归档；不带编号 = 当前话题 |
| `/dsh restore #3` | `/dsh 恢复 #3` | 恢复归档话题（7 天内） |
| `/dsh list` | `/dsh 话题`、`/dsh topics` | 列出话题 |
| `/dsh 话题 #3` | `/dsh list #3` | 查看 #3 详情并切换过去 |
| `/dsh files` | — | 文件柜：看自己的文件（详见 5.6） |
| `/dsh files rm <序号\|名字>` | — | 删自己的文件 |
| `/dsh files send <序号\|名字>` | — | 把自己的文件重新发回聊天 |
| `/dsh files mkdir <名字>` | — | 在文件柜里建子文件夹 |
| `/dsh files all` | — | 主人专用：看所有人的文件 |
| `/dsh files users` | — | 主人专用：看各人占用 |
| `/dsh 审批` | `/dsh 授权列表` | 看待审批申请 + 已授权的人（审批人） |
| `/dsh 批准 A1 [小时]` | — | 批准申请（省略=默认时长，0=永久） |
| `/dsh 拒绝 A1 [理由]` | — | 驳回申请 |
| `/dsh 撤销 <QQ>` | — | 收回某人的 /dsh 权限 |
| `/dsh 实验开启` | `/dsh 实验打开`、`/dsh experiment on` | 进入实验模式二次确认（生成 6 位码） |
| `/dsh 实验确认 <6位码>` | — | 确认码对上即开启，最长 24 小时 |
| `/dsh 实验状态` | `/dsh 实验 status` | 看实验模式剩余时间 |
| `/dsh 实验关闭` | `/dsh 实验 off` | 提前关闭实验模式 |
| `/dsh help` | `/dsh`（不带参数） | 分场景帮助总览（详见第 10 节） |
| `/dsh help 话题\|文件\|权限\|实验\|排障\|全部` | `/dsh help 2`～`/dsh help 7` | 只显示某场景的帮助 |

**小技巧**
- 编号写法容错：`#3`、`3`、`第3个`、`话题3` 都认；中文全角括号 `（ ）` 也认。
- 任务正文如果碰巧以 `new`/`del` 开头（比如"new 一个页面"），在正文前加 `-- ` 强制当任务：`/dsh -- new 一个页面`。
- 默认**不限时**：任务会一直跑到完成或你说停；想设上限用 `/dsh --timeout 600 <任务>`。
- 权限：沿用桥的白名单（`[permission]`）。
- 群聊：话题指令只在私聊可用，群里发会提示"话题功能只在私聊启用"。

## 4. 典型用法

### 4.1 从零开始

```
你: /dsh 帮我看看 sleepy 那边离线设备的截图为什么是黑白的
墨: 🛠 #1（遗留·af8e6f） 已受理（不限时，/dsh stop 可停）：帮我看看 sleepy 那边离线设备的截图为什么是黑白的
    …（dsh 干活；默认完成后不刷屏，结果回灌给墨，由墨组织回复）
你: 那现在呢
墨: 黑白是因为 xxx，已经改好 /css/glass/main.css …
```

### 4.2 第二天接着聊（同一话题）

```
你: /dsh 昨天那个黑白的事，把离线图也顺便压一下
墨: 🛠 #1（修离线截图） 已受理（不限时，/dsh stop 可停）：…
```

如果距上次使用超过 24 小时：

```
墨: 🛠 #2（新话题） 已受理（不限时，/dsh stop 可停）：…
```

### 4.3 主动开新话题

```
你: /dsh new
墨: 🗒 已创建 #2（新话题）；之后的任务会落在这个话题（可用 /dsh set <新名字> 改名）。
你: /dsh 换个方向，做个课表提醒
墨: 🛠 #2（新话题） 已受理（不限时，/dsh stop 可停）：换个方向，做个课表提醒
      （任务完成后话题名会被 dsh 起的名字替换，比如「课表提醒」）
```

### 4.4 查看 / 改名 / 归档 / 恢复

```
你: /dsh list
墨: 📚 话题列表（当前 #2（课表提醒））
    #1（修离线截图）· 最后使用 2 天前
    #2（课表提醒）· 最后使用 刚刚 ← 当前

你: /dsh set 课表每日提醒
墨: ✏️ #2（课表每日提醒） 已改名

你: /dsh del #1
墨: 🗄 #1（修离线截图） 已归档，7 天后自动删除；期间可用 /dsh restore #1

你: /dsh #1 继续修
墨: #1 已归档，先 /dsh restore #1 才能继续

你: /dsh restore #1
墨: ♻️ #1（修离线截图） 已恢复，之后的任务会继续用它。
```

### 4.5 指定话题干活（会把该话题设为当前）

```
你: /dsh #1 只回复：回到一号话题
墨: 🛠 #1（修离线截图） 已受理（不限时，/dsh stop 可停）：只回复：回到一号话题
```

### 4.6 记不住命令

```
你: /dsh
墨: 🛠 /dsh 用法（大肥鱼的活儿都收在这儿啦～）
      /dsh <任务> …
      /dsh help 话题 | 文件 | 权限 | 实验 | 排障 | 全部
```

## 5. dsh 向你提问 / 交付文件 / Office

### 5.1 提问：dsh 会等你回答（同一进程继续）

- dsh 需要拍板时，会调用 **专门的 ask 工具**（`mcp__ask__ask_user`），桥把它转成 QQ 消息：
  ```
  ❓ #3（名字） dsh 需要你确认：
  选 A 还是 B？
  参考选项：
    1. A
    2. B
  直接回一句话就是答案，15 分钟内有效（以 / 开头的命令不算答案）。
  ```
- 你回一句话就是答案（带选项时可回编号）。桥把答案写回给 dsh，它**在同一个进程里接着干**，不再重启。
- 等待期间：
  - 你发的**文件/图片**照常收进你的文件柜（`files/<你的QQ号>/`），但**不会被当成答案**；
  - 你发 `/dsh` 新任务 → 旧提问自动作废；
  - 等待超过 `ask_timeout`（默认 15 分钟）→ 工具返回"没等到回答"，dsh 自己决定下一步（会说明卡在哪）。
- **备用通道**：如果 ask 工具不可用（比如 profile 没挂 mcp-client），dsh 会退回写 `ask-requests/*.json`，
  桥用「发问题 → 收回答 → 续跑同一会话」的老流程兜底——两种通道都测过。

### 5.2 交付文件：dsh 产出的文件会发回 QQ

dsh 用 `present` 声明要交给你的文件（Word/PPT/Excel、代码、压缩包等），桥会：
- 单文件 → 直接上传到当前私聊
- 多文件或大文件 → 打包成 zip 再发
- 同时回一句 `📦 大肥鱼交作业啦（N 个）：…`

**异常救回**：任务被你叫停（`/dsh stop`）/ 卡死 / 循环判死 / 异常中断时，dsh 常来不及 `present`。桥这时会扫一遍工作区，
把**本轮新产出的文件**（docx/xlsx/pptx/pdf/图片/zip/md…，单文件默认 ≤20 MB，最多 8 个）直接发给你，
并附一句 `📎 …先发给你：xxx`，不会让你白等一场。

> 依赖 NapCat 的文件上传接口；SnowLuma 适配器已提供该接口，实测可用。发不出去时会在日志里留记录。

### 5.3 Office 文档（Word / PPT / Excel）

dsh 已挂 Office 技能（技能名 `office-docx` / `office-pptx` / `office-xlsx` 等），可以直接：
- 读你发的 `.docx/.pptx/.xlsx`，做结构检查、改内容
- 生成新的文档并用 `present` 交付

用的 Python 环境是 `/opt/dsh-office-venv/bin/python`（已装 python-docx / python-pptx / openpyxl），
这条约定写在每个话题工作区的 `AGENTS.md` 里，dsh 会照做。

### 5.4 盯进度与叫停：`/dsh peek` 和 `/dsh stop`

**默认不给任务设时间预算**——模型估不准自己要多久，硬限时往往砍掉快做完的活。控制权交给你：

- `/dsh peek`（也认 `/dsh 状态`、`/dsh 进展`、`/dsh 在干嘛`）随时看它现在在干什么：
  ```
  👀 #1（课表转Word） 正在干活：已 4 分 12 秒
  进度：第 1 轮第 18 步 · 最后动静 12 秒前
  现在在跑：bash · python scripts/build_timetable.py
  最近动静：
    · 生成 课程表.docx（40 KB）
  预算：不限时，/dsh stop 可停
  ```
  空闲时它会告诉你最近一次任务的结果和用时。
- `/dsh stop`（也认 `/dsh 停止`）：立刻停下，一般 2 秒内响应。停下后：
  - 发一句 `🛑 按你的要求停下了`；
  - **本轮已产出的文件照样发给你**（和异常救回同一套逻辑）；
  - 会话保留，之后照样可以接着派活。
- `/dsh stop 全部`：连排队中的任务一起清掉。
- 实验模式窗口内 `/dsh` 命令被禁用，但 **`/dsh stop`、`/dsh peek`/`status`、`/dsh queue` 仍然可用**（应急开关）。

**想自己设上限**：`/dsh --timeout 600 <任务>`（秒），不写就是不限时。
另有两条自动兜底（不是时间预算）：
- 死锁兜底：**连续 10 分钟没有任何输出**且进程静默 → 判死锁终止（`dsh.heartbeat_seconds`）；
- 循环兜底：同一行输出重复 25 次 → 判死循环终止。

## 5.5 文件会交给谁（文件路由）

你发文件时，桥会先把文件存进**你自己的文件柜**（`files/<你的QQ号>/`，见 5.6），再决定这轮文件消息交给谁处理。
分两种模式，规则不一样：

### 5.5.1 普通模式（没开实验）

| 你发的内容 | 谁来处理 | 说明 |
|---|---|---|
| **文件**，没带 `/dsh` | **墨本人** | 墨会直接读文件（PDF/Word/Excel/PPT/文本/代码都行）并回答你，**不会自动丢给大肥鱼** |
| **文件 + 文字说明**，没带 `/dsh` | **墨本人** | 墨按你的说明看文件、回答；需要复杂处理时它会自己决定要不要派给大肥鱼 |
| 任意消息**带 `/dsh`** | **大肥鱼** | 文件路径会写进当次任务的【用户文件】提示里，大肥鱼直接读 |
| 纯文字，不带 `/dsh` | 墨 | 正常聊天，不碰大肥鱼 |

例子：

```
你: [课表.xlsx]                                  ← 墨直接打开看，回你课表内容
你: [课表.xlsx] 帮我排成每周计划                ← 墨看文件后回答（要动手改文件时会派给大肥鱼）
你: /dsh [课表.xlsx] 转成 Word 并按周排版       ← 文件交给大肥鱼，在话题里干活
```

> **和旧版的区别**：v0.12.x 会把纯文件消息先"拦住"、等你说要干什么；v0.13.0 起没 `/dsh` 的文件直接交给墨，
> 墨能看就自己看，不会再出现"文件发过去了却没人理"的干等。

### 5.5.2 实验模式（墨自主调度）

开了实验模式后，**由墨自己判断**要不要把文件交给大肥鱼：

| 你发的内容 | 行为 |
|---|---|
| **纯文件消息**（只有文件、没有一个字说明） | 只回一条**收到回执**，不打扰墨、也不派活——你说要做什么再说 |
| **文件 + 文字说明** | 墨拿到「文件 + 你的说明」后**自己决定**：能直接答就自己答，需要大肥鱼动手就派活 |
| 带 `/dsh` 的消息 | 实验期间 `/dsh` 命令暂时收起（`stop`/`peek`/`status`/`queue` 除外），会提示你直接说人话 |

例子：

```
你: [报价单.pdf]                                 ← 只回执："文件收好啦～要拿它做什么？"
你: [报价单.pdf] 帮我核一下里面三个数字对不对      ← 墨自己读 PDF、核对、回你结论
你: [报价单.pdf] 照着这个格式做一份新报价单        ← 墨判断要动手，派给大肥鱼在话题里做
```

> 一句话记：**普通模式「没 /dsh 就归墨，有 /dsh 归大肥鱼」；实验模式「墨自己拍板」**。

## 5.6 文件管理（按 QQ 号分目录）

### 5.6.1 目录与权限

用户发来的文件统一存在**工作区根目录**下的按 QQ 号分目录里，**跨话题共用一份**，换话题不会清空：

```
/root/DSH-work/mai/
└── files/
    ├── 2953679189/          # 主人的文件柜
    │   ├── index.json       # 文件索引（内部用，别删，也别当普通文件发出去）
    │   ├── 课表.xlsx
    │   └── 项目A/           # 子文件夹（/dsh files mkdir 建的）
    └── 123456789/           # 别人的文件柜，只有本人（和主人）能看
        └── ...
```

**权限矩阵**：

| 操作 | 普通用户 | 主人（QQ 2953679189） |
|---|---|---|
| `/dsh files` 看自己的文件 | ✅ | ✅ |
| `/dsh files rm/send/mkdir`（自己的） | ✅ | ✅ |
| 看/管**别人**的文件 | ❌ 会被告知没权限 | ✅ |
| `/dsh files all`（所有人文件总览） | ❌ | ✅ |
| `/dsh files users`（各人占用） | ❌ | ✅ |
| 让大肥鱼帮忙读写别人的目录 | ❌ 文件工具会拒绝越界 | ✅ |

> 隔离是**目录级**的：桥和文件工具都会做路径校验，`../`、软链接这类越界手法会被拒。
> 文件柜里除了你的文件，只有 `index.json`（索引），它由插件维护，不要删、也不建议手动改。

### 5.6.2 命令（都在 `/dsh files` 下）

| 命令 | 作用 |
|---|---|
| `/dsh files` | 列自己的文件（带序号、名字、大小、时间），子目录可以进去看 |
| `/dsh files send <序号\|名字>` | 把自己的某个文件**重新发回聊天**（发丢了、换设备了就用它） |
| `/dsh files rm <序号\|名字>` | 删掉自己的文件（**删了不可恢复**，不确定就先 `send` 备份） |
| `/dsh files mkdir <名字>` | 在自己的文件柜里建子文件夹，按项目归置 |
| `/dsh files all` | **主人专用**：看所有人的文件 |
| `/dsh files users` | **主人专用**：看每个人占了多少空间 |

- 序号是 `/dsh files` 列表里显示的编号，**每次列出来可能变**，删/发之前先看一眼。
- 名字带空格/中文都可以，找不到时会提示你重新列一遍。
- 非主人发 `all`/`users` 会收到"没权限"的提示，不会泄露别人的文件名。

### 5.6.3 保留策略

- **长期保留**：文件不会因为任务结束或话题归档被删，换话题也还在。
- **自己删**：只有你自己（或主人）能删，用 `/dsh files rm`。
- **大小限制**：单文件默认最大 **50 MB**（配置项 `dsh.upload_max_mb`），超过会提示取不到。
- **索引**：`index.json` 只记录文件清单/大小/时间，不含文件内容。
- 以后可能加**配额 / 自动清理**（比如太久没动的大文件），到时候会在更新说明里写清楚，不会悄悄删你的东西。

> 话题目录里的 `uploads/` 是 v0.12.x 及更早版本的旧文件位置，历史文件还能读，但新文件一律进上面的
> `files/<QQ号>/`。旧文件要不要搬，用大肥鱼在话题里处理即可。

### 5.6.4 墨直接读文件（file-reader）

墨装了 file-reader（打补丁后走桥同款 Host adapter API 取文件），**能直接读你发来的文件**：

- 支持：PDF、Word（.docx）、Excel（.xlsx）、PPT（.pptx）、纯文本、常见代码文件；图片也能看。
- 你可以直接问文件里的内容，比如「这份合同第三条写了啥」「把 Excel 里的总数算一下」。
- 两条 file-reader 的命令（**不是** `/dsh` 子命令，直接发）：
  - `/文件状态` —— 看墨当前手上有哪些文件、读取是否正常；
  - `/清文件` —— 清掉墨当前的文件读取上下文（**不会**删你文件柜里的原文件）。
- 需要大动干戈（改文档、批量转格式、生成新文件）时，再带 `/dsh` 让大肥鱼接手。

## 6.5 权限审批（没权限的人怎么用）

桥默认是白名单制：名单外的人发 `/dsh` 会被拦。开启审批后就不一样了：

1. 名单外的人发 `/dsh <任务>` → 桥不直接拒绝，而是**生成一张申请单**（编号 `A1`、`A2`…，默认 30 分钟有效），
   回复申请人：「🔐 你还没有用 /dsh 的权限，墨把申请单 A1 发给审批人啦～」
2. 审批人（配置 `permission.approvers`；**留空=只认白名单里的第一个人**，也就是你）会收到：
   ```
   🔐 权限申请 A1：
   某某（QQ号）想用 /dsh：<任务前 60 字>
   批准发 /dsh 批准 A1 [小时]（省略=默认 24 小时，0=永久）
   拒绝发 /dsh 拒绝 A1
   ```
3. 审批人回 `/dsh 批准 A1`（或 `/dsh 批准 A1 2` 给 2 小时、`/dsh 批准 A1 0` 给永久）：
   - 申请人收到「🎉 你的 /dsh 权限批下来啦～」；
   - 授权写入 `grants.json`，到期自动失效（永久授权则不过期）。
4. 其它审批指令：
   | 命令 | 作用 |
   |---|---|
   | `/dsh 审批`（同 `/dsh 授权列表`） | 看待审批的申请单 + 已授权的人 |
   | `/dsh 拒绝 A1 [理由]` | 驳回申请 |
   | `/dsh 撤销 <QQ>` | 收回某人的授权 |
   | `/dsh 批准 <QQ> [小时]` | 直接给某人授权（不用申请单） |

配置项（`[permission]`）：`approval_enabled`（默认 true）、`approvers`（审批人；留空=白名单第一个）、
`approval_hours`（批准后有效期，0=永久）、`approval_ttl_minutes`（申请单有效期）。

> 审批人第一次收不到申请单时别急：桥要记住审批人的私聊 stream 才能发通知，审批人先随便发一句话，
> 待审批的申请单会自动补发过去。

## 8. 常见问题

**Q：为什么我发 `/dsh` 墨不回我？**
A：这是故意的——命令由桥处理，拦截等级 1，消息不进墨的对话流程，避免墨接话茬。想聊天直接说普通句子就行。

**Q：同时能跑几个任务？**
A：全局串行，一次一个 dsh 进程；第二个任务会排队（默认最多 3 个），排满会直接拒绝。

**Q：话题之间会不会串？**
A：不会。会话独立（`--session-id`）、目录独立；任务上下文/提问都只对当前话题生效。
唯一例外是**文件柜**：用户文件按 QQ 号存在 `files/<QQ号>/`，跨话题共用一份，换话题不会弄丢（详见 5.6）。

**Q：删掉的话题还能救回来吗？**
A：7 天内 `/dsh restore #N`；超过 7 天目录和记录一起清掉，**编号会被后续新话题复用**，所以别用编号当长期标识。

**Q：为什么我 `#1` 叫「遗留·af8e6f」？**
A：那是认领了你原来的工作目录。改名不影响目录和会话，`/dsh set` 随便改。

**Q：dsh 会忘事吗？**
A：话题会话是持久的，但上下文太长会被压缩。重要结论让它写进工作区文件（它能看到自己的目录）。

**Q：报错会去哪？**
A：被停、死锁兜底、疑似死循环这类会直接发一条原因到聊天；工具级失败明细目前只在 `(all)` 的合并转发卡片里（完整报错上报在 P3）。

**Q：任务跑太久怎么办？为什么不像以前那样限时？**
A：默认不再按秒砍任务——模型估不准自己的耗时，硬限时常常在快做完时砍掉。现在：
`/dsh peek` 看它在干嘛，觉得不对就 `/dsh stop` 停（2 秒内响应，已产出的文件会发回来）。
确实想设上限时用 `/dsh --timeout 600 <任务>`；另有两条自动兜底：连续 10 分钟零输出判死锁、同一行重复 25 次判循环。

**Q：任务被停/中断了，已经做出来的文件会丢吗？**
A：不会。终止时桥会扫工作区，把本轮新产出的文件（文档/图片/压缩包等）直接发出来；想接着改就说一句
「用这个话题继续把 xxx 补完」，会话还在。

**Q：任务失败，为什么以前什么都不显示？**
A：v0.11.1 之前，dsh 以 `{"type":"error"}` 直接退出（典型是会话被别的进程占用）时桥会当成「成功的空输出」，于是你什么都看不到。现在会判失败并发 `❌ 大肥鱼干活失败了：<原因>`，`/dsh peek` 和 `dsh_status` 里也能看到原因。

**Q：`dsh_home` 是什么？为什么要让 headless 单独一个 DSH_HOME？**
A：DSH_HOME 是 dsh 的「数据目录」（会话库、凭据、配置）。桥和 dsh Web GUI 默认共用 `~/.dsh`，于是 GUI 一旦打开某条会话就会持有写锁，桥续跑同一个会话时会报 `already owned by an active write handle`。
把 `dsh.dsh_home` 配成独立目录（比如 `/root/.dsh-headless`）后：
- 桥的会话只存在 `/root/.dsh-headless/sessions/`，GUI 看不到、也不会抢锁；
- GUI 的会话仍在 `~/.dsh/sessions/`，两边互不影响；
- 新目录里**必须**有一份 `.credentials.yaml`（否则 dsh 会报 `MISSING_CREDENTIAL`）和 `profiles/headless/`。
清理任一边的会话都不会影响另一边。

**Q：为什么提示「会话正被 Web GUI 打开着」？**
A：dsh 的会话同一时间只能有一个写入方。你在 Web GUI（183.66.27.21:12288）里打开了这个话题的会话时，
桥就续不上。v0.11.1 起桥会**自动改用一条新会话继续**（旧会话的上下文不继承）；想接着用旧会话，在 GUI 里关掉它再派活即可。

**Q：我发文件会被 dsh 自己捡起来处理吗？**
A：看你有没有带 `/dsh`、以及有没有开实验模式（完整规则见 5.5）：
- 普通模式：**没带 `/dsh` 就交给墨本人**，墨直接读文件回答，不会自动丢给大肥鱼；带了 `/dsh` 才给大肥鱼。
- 实验模式：墨自己判断要不要派给大肥鱼；**纯文件消息只回执、不打扰**，文件+文字说明才会触发决策。

**Q：我的文件存在哪？别人能看到吗？**
A：存在 `/root/DSH-work/mai/files/<你的QQ号>/`，按 QQ 号隔离：你只能看/管自己的，只有主人（QQ 2953679189）
能 `/dsh files all`、`/dsh files users` 看所有人。文件柜里还有个 `index.json` 索引，是插件内部用的，别删。

**Q：文件会过期/被自动删吗？**
A：不会。文件长期保留，只有你自己 `/dsh files rm` 或主人动手才会删；换话题、归档话题都不影响。
单文件默认最大 50 MB（`dsh.upload_max_mb`）；以后可能加配额/自动清理，会提前在更新说明里写。

**Q：文件发丢了 / 想再看一遍怎么办？**
A：`/dsh files` 找到它，再 `/dsh files send <序号|名字>` 重新发回聊天；建子文件夹用 `/dsh files mkdir <名字>`。

**Q：怎么看某个场景的用法？**
A：`/dsh help` 是总览 + 场景入口；`/dsh help 话题|文件|权限|实验|排障|全部` 看单个场景（也认中文别名和数字 1–7，详见第 10 节）。

**Q：实验模式还要先去 MaiBot 面板开总开关吗？**
A：不用了。v0.13.0 起直接在 QQ 里 `/dsh 实验开启` → `/dsh 实验确认 <6位码>` 就能开，最长 24 小时、到期自动关
（详见第 11 节）。

**Q：`/dsh status` 和 `/dsh peek` 有什么区别？**
A：没有区别，`status` 是 `peek` 的英文别名；`/dsh queue` 单独看排队情况（第几位、还有几条）。

**Q：定时任务算哪个话题？**
A：创建时记录所属话题；到点在那个话题里执行。旧的定时任务没有话题记录，会落在当时的当前话题。

**Q：群聊能用话题吗？**
A：暂时不能（`topic.private_only=true`）。群里走旧行为：一个群一个工作目录、任务串行。

**Q：旧的无斜杠写法（`/新建`、`/话题`）还能用吗？**
A：已收起，统一用 `/dsh new`、`/dsh list` 等。发旧写法会被当普通文字，可能被墨接话。

## 10. 帮助（分场景）

v0.13.0 起 `/dsh help` **不再是一大坨**：默认只给一屏总览 + 场景入口，想看细的按场景翻。

| 命令 | 看什么 | 数字 |
|---|---|---|
| `/dsh help`（或 `/dsh` / `/dsh 帮助` / `/dsh ?`） | **默认**：高频命令 + 场景入口（一屏，≤25 行） | `1` |
| `/dsh help 话题` | 建话题、列表、改名、归档、恢复 | `2` |
| `/dsh help 文件` | `/dsh files` 全部子命令、文件路由、保留策略 | `3` |
| `/dsh help 权限` | 审批、批准、拒绝、撤销 | `4` |
| `/dsh help 实验` | 实验模式开启/确认/状态/关闭 | `5` |
| `/dsh help 排障` | peek/status、queue、stop、常见故障 | `6` |
| `/dsh help 全部` | 按场景排好的完整命令表（≤60 行） | `7` |

- 场景名**认中文别名**：`新手指南`=默认、`文件柜`=文件、`审批`=权限、`实验模式`=实验、`故障`=排障、`所有`=全部。
- 也认英文和数字：`/dsh help topic`、`/dsh help file`、`/dsh help 3` 都行。
- 每个场景的最后一行都能回到总览：`发 /dsh help 看全部入口～`。
- 帮助文案的最终版本在 `bridge2/docs/help-copy.md`（key：`HELP_DEFAULT`、`HELP_TOPIC`、`HELP_FILE`、
  `HELP_PERMISSION`、`HELP_EXPERIMENT`、`HELP_TROUBLE`、`HELP_ALL`），改文案以那份为准。

> 记不住命令时先 `/dsh help`，大部分问题都能顺着场景入口找到；实在找不到就 `/dsh help 全部` 搜。

## 11. 🧪 实验功能：让墨自己调度（最长 24 小时）

> 开了之后**你不用再打 /dsh 命令**，直接用大白话跟墨说，它自己建/切话题、派活。
> 因为还不稳定，所以是实验功能：只能临时开 24 小时，且需要二次确认。

### 开启（两步，不用去面板）

> v0.13.0 起**不用先在 MaiBot 面板打开总开关**：QQ 里发两句话就能开。
> （`experimental.agent_tools` 仍是总闸、默认开；哪天想彻底禁用，再把它关掉即可。）

1. 发 `/dsh 实验开启`，桥会回一条 **二次确认**（确认码 10 分钟内有效）：
   ```
   🧪 实验功能（墨可以自己调度大肥鱼）· 二次确认
   开启后 24 小时内：
   · /dsh 命令全部临时收起来（/dsh stop、/dsh peek 还能用）
   · 墨可以直接建/切/改/删话题、派活，不用你打命令啦
   · 到期自动关，也可以 /dsh 实验关闭 提前收摊

   确认码：153205
   回复 /dsh 实验确认 153205（10 分钟内有效）
   ```
2. 回 `/dsh 实验确认 153205` → 开启成功，24 小时倒计时开始；之后随时 `/dsh 实验状态` 看剩余时间。

> 没收到确认？再发一次 `/dsh 实验开启` 会重新生成确认码；过期了也重新发。
> 实验期间发文件的路由会变（纯文件只回执、文件+说明由墨自己决定），见 5.5.2。

### 开启期间

- **`/dsh` 命令暂时收起来**（只剩 `/dsh 实验状态`、`/dsh 实验关闭`，外加应急的 `/dsh stop`、`/dsh peek`/`status`、`/dsh queue`）
- 墨可以自主调用这些工具（不用你说"命令"）：

| 墨的工具 | 作用 |
|---|---|
| `dsh_topic_list` | 看有哪些话题、当前是哪个 |
| `dsh_topic_new` | 新建话题（"开个新话题"） |
| `dsh_topic_rename` | 改话题名 |
| `dsh_topic_archive` | 归档话题（**必须带 confirm=true**，墨要先问你同意） |
| `dsh_topic_restore` | 恢复归档话题 |
| `dsh_run` | 派活（新增 `topic` 参数，可指定话题） |

- 用法举例（直接说人话）：
  ```
  你: 帮我把课表整理成每周计划，单独开个话题
  墨: （调用 dsh_topic_new → dsh_run，把课表任务放进新话题）
  你: 那个话题改名叫「课表周计划」
  墨: （dsh_topic_rename）
  你: 上一个话题不用了，归档吧
  墨: （先问一句确认 → dsh_topic_archive confirm=true）
  ```

### 关闭

- **自动**：开启满 24 小时自动关闭（会发消息告诉你，`/dsh` 恢复、墨不再自主调度）
- **手动**：`/dsh 实验关闭`
- **随时查看**：`/dsh 实验状态` 看还剩多久（没开、待确认也会告诉你当前状态）
- **总闸（平时不用动）**：把插件设置里的 `experimental.agent_tools` 关掉会立刻关闭，并禁止再开启

### 安全边界

- 二次确认码 **10 分钟**有效，过期要重新 `/dsh 实验开启`
- 开启**不用面板**（QQ 指令就是入口），但必须本人回 `/dsh 实验确认 <码>` 才生效，防误触、也防别人替你开
- 最长 **24 小时**（配置里填更大也只按 24 算），不可续期（想继续就再走一遍开启流程）
- 归档是破坏性操作：墨必须先征得你同意，调用时带 `confirm=true`，否则工具直接拒绝
- 只对**私聊**生效；权限仍受 `[permission]` 白名单约束
- 实验期间 `/dsh 实验状态` 随时可看剩余时间
